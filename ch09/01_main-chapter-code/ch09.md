# 第 9 章导读:监督微调(SFT)—— 教模型扮演 assistant

> 这是 MiniMind 教程的第 9 章。完整的交互版见 [`ch09.ipynb`](./ch09.ipynb)。

## 章节摘要

前 8 章我们造了一台能「续写文本」的引擎(预训练),但这台引擎只会续写 —— 不知道「被问到问题时应该回答」。

**监督微调(Supervised Fine-Tuning, SFT)** 用对话数据教会预训练模型「对话」:给定用户的问题,生成 assistant 的回复。

本章对应 minimind 的核心代码:
- `dataset/lm_dataset.py:58-119`(`SFTDataset` 类 + `generate_labels`)
- `trainer/train_full_sft.py`(训练脚本)

⭐ **核心**是 **answer-only loss masking** —— 只让模型从 assistant 的回复 token 学习,忽略 prompt(user/system)部分。这是 SFT 与预训练最本质的区别。

## 学习目标

读完本章后,你应该能:

- 解释预训练和 SFT 解决的不同问题(学语言 vs 学对话)
- 说出 SFT 数据格式(`{"conversations":[{role, content}]}`)和 chat_template 渲染的过程
- **手动实现 `generate_labels`**:从 token 序列中定位 assistant span,设置 loss masking
- 可视化哪些 token 参与 loss(assistant),哪些被忽略(user/system)
- 解释 `pre_processing_chat`(20% 加 system)和 `post_processing_chat`(80% 去空 think)的作用
- 对比 SFT vs Pretrain 的 4 个关键差异(学习率、label、max_seq_len、from_weight)
- 解释为什么 SFT 学习率(1e-5)比预训练(5e-4)低 50 倍(catastrophic forgetting)

## 术语表

| 术语 | 英文 | 解释 |
|---|---|---|
| 监督微调 | Supervised Fine-Tuning (SFT) | 用标注的对话数据微调预训练模型,教它对话 |
| 损失掩码 | Loss Masking | 只让部分 token 参与 loss 计算;SFT 中只保留 assistant token |
| 仅回答掩码 | Answer-only Masking | 只从 assistant 回复学习,prompt 部分标为 -100 |
| 对话模板 | chat_template | 把 `{role, content}` 列表渲染成 token 序列的模板 |
| 角色边界标记 | `<\|im_start\|>` / `<\|im_end\|>` | ChatML 格式的角色边界标记 |
| 忽略索引 | ignore_index (-100) | CE loss 中标记为该值的 label 不参与计算 |
| 灾难性遗忘 | Catastrophic Forgetting | 学习新任务时用大学习率导致旧知识被覆盖 |
| 续写 | Continuation | 预训练模型的行为:给定前文,预测下一个 token |
| 生成提示 | add_generation_prompt | 推理时在末尾加 `<bos>assistant\n` 提示模型开始生成 |

## SFT vs Pretrain 对照

| 维度 | 预训练 | SFT | 倍数 |
|---|---|---|---|
| 学习率 | 5e-4 | **1e-5** | 低 50 倍 |
| label 来源 | 全部 token | **仅 assistant token** | ~30-50% |
| max_seq_len | 340 | **768** | 2.3x |
| from_weight | none(从头) | **pretrain** | 继续训练 |
| 数据格式 | `{"text":"..."}` | `{"conversations":[...]}` | - |
| epochs | 1 | 2 | 2x |

## 核心认知

> SFT 的灵魂是 **answer-only loss masking**:在 token 序列中精确定位每个 assistant 回复的 span(`<bos>assistant\n` 到 `<eos>\n`),只让这些 token 参与 loss 计算。模型因此学会「在 assistant 位置生成有意义的回复」,而不是学会「模仿用户提问」。
