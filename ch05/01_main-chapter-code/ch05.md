# 第 5 章导读:FFN 与 Block —— SwiGLU 与残差流

> 这是 MiniMind 教程的第 5 章。完整的交互版见 [`ch05.ipynb`](./ch05.ipynb)。

## 章节摘要

本章从最朴素的 `Linear→ReLU→Linear` 出发,一步步演进到 minimind 使用的 **SwiGLU**(`model/model_minimind.py:136-146`),再扩展到 **MOEFeedForward**(148-176),最后组装成完整的 **MiniMindBlock**(178-194)。涵盖 GLU 门控原理、SiLU 激活函数对比、`intermediate_size=2432` 的 π 公式、MoE 的 top-1 路由与 aux_loss 负载均衡,以及 Pre-Norm 残差连接。

## 学习目标

读完本章后,你应该能:

- 解释 FFN 在 Transformer 中的职责(知识存储 vs Attention 的信息路由)
- 手写 SwiGLU 的前向传播:`down_proj(silu(gate_proj(x)) * up_proj(x))`
- 说明为什么用 SiLU 而不是 ReLU(负区有梯度、平滑)
- 推导 `intermediate_size = ⌈768·π/64⌉·64 = 2432` 的参数预算逻辑
- 描述 MoE 的 router 路由、`index_add_` 累加、aux_loss 均衡机制
- 解释 Pre-Norm 残差连接为什么比 Post-Norm 更稳定
- 画出 MiniMindBlock 的数据流(两个残差子层)

## 术语表

| 术语 | 英文 | 解释 |
|---|---|---|
| 前馈网络 | FFN (FeedForward Network) | 每个 token 独立经过的两层 MLP |
| 门控线性单元 | GLU (Gated Linear Unit) | 用 gate 路径做软性过滤的 FFN |
| SwiGLU | SwiGLU (SiLU-Gated Linear Unit) | SiLU 激活的 GLU,Llama/minimind 使用 |
| SiLU 激活 | SiLU / Swish | $x \cdot \sigma(x)$,负区有小负值 |
| 门控矩阵 | gate_proj | SwiGLU 的门控投影路径 |
| 中间层宽度 | intermediate_size | FFN 升维后的维度,minimind = 2432 |
| 混合专家 | MoE (Mixture of Experts) | 多个 FFN 专家 + router 路由 |
| 路由器 | Router / Gate | `hidden_size → num_experts` 的线性层 |
| 负载均衡 loss | Auxiliary Loss (aux_loss) | 惩罚 MoE router 负载不均衡 |
| 残差连接 | Residual Connection | $h + F(h)$,梯度高速公路 |
| Pre-Norm | Pre-Norm | LayerNorm 在残差内部,训练更稳定 |
| 残差流 | Residual Stream | 贯穿所有 Block 的隐藏状态 `h` |

## 核心认知

> FFN 是 Transformer 的「知识仓库」—— 占每层 76% 的参数。SwiGLU 用门控 + SiLU 激活换取更强的表达力,而 `intermediate_size=⌈768·π/64⌉·64=2432` 在参数预算和容量间取平衡。MoE 让这个仓库扩大 3 倍却不增加计算成本。残差连接则是让这一切能堆叠 8 层的「生命线」。
