## 二、核心对比: 分类精确率 (统一 20 条验证集)

| 模型 | 分类精确率 | 关键发现 |
|---|---|---|
| H1 Dense SFT | **50%** | 基线 |
| H1 PLE SFT | **50%** | PLE=Dense (分类) |
| H1 Dense DPO v3 | **50%** | DPO 不改变分类 |
| H1 PLE DPO v3 | **50%** | 同上 |
| H1 附件增强 DPO | **50%** | 附件注入不改变分类 |
| H1 修复版 DPO | **50%** | mask 修复也不改变分类 |
| **H2 Dense SFT** | **45%** | 略低 (从零无预热) |

**结论**: 所有 H1 模型分类精确率**完全相同 (50%)**。分类能力由 **SFT 数据质量**决定, **DPO/架构/附件注入均不改变分类** — 印证"DPO 是偏好对齐, 与分类能力正交"。

## 三、核心对比: 附件问答自然度 (同一样本)

| 模型 | 输出 | 评价 |
|---|---|---|
| H1 Dense SFT | "为'招商信诺大家寿险..." | 引用附件但生硬 |
| H1 PLE SFT | "Dear all:截止目前在明天下午 12 月份有限公司将..." | **语句破碎** |
| H1 修复版 DPO | "为'招商信诺大家寿险..." | 与 SFT 同 (过拟合无改善) |
| **H2 Dense SFT** | "Dear,这个开发及我司系统开发及信息安全,这个是业务部门负责人..." | **最自然、语义连贯** |

**结论**: **H2 (更大模型) 附件理解显著优于 H1** — 输出更自然、更贴合附件内容。H1 小模型无论 SFT/DPO 都受容量限制。

## 五、DPO 三阶段演进 (H1)

| 版本 | 数据 | 问题 | Loss |
|---|---|---|---|
| v3 DPO | 3000对 (模板) | 长度偏置 20x | 0.62 (空转) |
| 附件增强 DPO | 6799对 (附件注入) | **mask 截断** (loss 恒 0.69) | 0.69 |
| **修复版 DPO** | 910 健康对 × 2048 | 修复后生效, 但 3ep 过拟合 | **0.0082→0.0000** |

**核心教训** (已固化到 SKILL.md 陷阱 #11):
1. **mask 截断** = DPO 空转最隐蔽原因 (loss 恒 0.6931, 需前置检查)
2. **长度偏置** (模板负样本) = 次因 (健康集 e3 长度比 1.7x 解决)
3. **过拟合** = 修复后新问题 (1-2 ep 早停)

## 六、最终结论

1. **数据 > 架构 > DPO**: 分类由 SFT 数据决定 (全模型 50%); 附件理解由模型容量决定 (H2 自然 vs H1 生硬)
2. **DPO 在 H1 上价值有限**: 过拟合窗口窄 (Epoch 1 后即退化), 且不改变下游任务
3. **PLE = Dense (训练期)**: 参数 +62% 但效果相同, 价值仅在 ESP32 部署
4. **H2 是更优方向**: 附件理解显著更好, 但需 GPU 环境跑 DPO (AMD 890M 不可行)
5. **环境瓶颈**: AMD 890M 集成显卡限制 H2 DPO + 硬负样本生成, 需 NVIDIA GPU
