# 第 3 章导读:配置 —— 每个超参数为何这样选

> 这是 MiniMind 教程的第 3 章。完整的交互版见 [`ch03.ipynb`](./ch03.ipynb)。

## 章节摘要

本章逐行拆解 `MiniMindConfig`(`MiniMindConfig — model_minimind.py:~10-50 (@67f114a)`)的每一个超参数,解释**为什么是这个值**。这不是枯燥的 API 文档,而是一场参数预算的「精算」—— 64M 参数如何在 embedding、attention、FFN 之间分配,GQA 为什么省 50% KV cache,SwiGLU 的宽度为什么是 $\lceil d\pi/64 \rceil \times 64$,以及为什么 minimind 与 Qwen3 逐字段对齐。

## 学习目标

读完本章后,你应该能:

- 说出 `MiniMindConfig` 的 18 个核心字段及其默认值
- 解释 `hidden_size=768` 为什么避开表示瓶颈(MobileLLM 论文)
- 手算 GQA 省了多少 KV cache 参数和推理显存
- 推导 `intermediate_size=2432` 的来源($\lceil 768 \times \pi / 64 \rceil \times 64$)
- 解释 `rope_theta=1e6` 和 YaRN 外推(factor=16)的工作原理
- 理解 `tie_word_embeddings=True` 省了多少参数
- 计算 dense(64M)和 MoE(198M total / 64M active)的精确参数量
- 解释 minimind 与 Qwen3 的权重级兼容(`load_state_dict(strict=True)`)

## 术语表

| 术语 | 英文 | 解释 |
|---|---|---|
| 隐藏维度 | hidden_size / d_model | 模型内部残差流的宽度,minimind = 768 |
| 表示瓶颈 | Representation Bottleneck | dim < 512 时模型严重欠拟合(MobileLLM 论文) |
| 分组查询注意力 | GQA (Grouped-Query Attention) | 多个 Q 头共享 KV,minimind 2:1 |
| 多查询注意力 | MQA (Multi-Query Attention) | 所有 Q 头共享 1 组 KV(GQA 的极端) |
| 头维度 | head_dim | 每个注意力头的维度,minimind = 96 |
| 旋转位置编码 | RoPE (Rotary Position Embedding) | 用旋转矩阵注入位置信息 |
| RoPE 基础频率 | rope_theta / rope_base | 控制旋转频率分布,minimind = 1e6 |
| 上下文外推 | YaRN (Yet another RoPE extensioN) | 混合插值/外推扩展上下文长度 |
| 门控线性单元 | GLU (Gated Linear Unit) | FFN 的门控机制 |
| SiLU 激活 | SiLU (Sigmoid Linear Unit) | $x \cdot \sigma(x)$,SwiGLU 的激活函数 |
| 绑定权重 | Tied Embeddings | 输入嵌入和输出投影共享同一矩阵 |
| 混合专家 | MoE (Mixture of Experts) | 多个 FFN 专家 + router 路由 |
| 激活参数量 | Active Parameters | MoE 中每个 token 实际经过的参数 |
| 负载均衡 loss | Auxiliary Loss (aux_loss) | 惩罚 MoE router 的负载不均衡 |

## 核心认知

> 每个超参数都不是随便选的。它们在参数预算(~64M)、表示能力、训练成本(¥3/2小时)和推理效率之间做了精确的工程取舍。而 minimind 与 Qwen3 的逐字段对齐,让这个 64M 的小模型能用整个 LLM 推理生态。
