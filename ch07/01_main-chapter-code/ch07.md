# 第 7 章导读:生成 —— logits 怎么变成文本

> 这是 MiniMind 教程的第 7 章。完整的交互版见 [`ch07.ipynb`](./ch07.ipynb)。

## 章节摘要

前 6 章我们追踪了「token id → embedding → 8 个 Block → lm_head → logits」的编码流水线。但 `logits` 是一个 `(batch, seq_len, vocab_size)` 的浮点矩阵 —— 它怎么变成人类能读的文字?这就是**生成(generation)**要解决的问题。

训练时模型只需一次 forward 算 loss;生成时需要**自回归地一次生成一个 token**,循环往复,直到遇到 EOS 或达到长度上限。本章对应 `model_minimind.py` 的 **256-288 行** —— 那个手写的 32 行 `generate` 方法,却支持 temperature、top-k、top-p、repetition penalty、KV cache、streamer 等全部现代生成特性。

本章遵循 **naive → compact** 路径:先写 15 行朴素 greedy 循环(无 KV cache),逐步加入 temperature / top-k / top-p / repetition penalty,最后拆解完整的 `generate`。

## 学习目标

读完本章后,你应该能:

- 解释自回归生成的 5 步循环(forward → 取最后 logits → 选 token → 拼回 → 重复)
- 手写朴素 greedy decoding 循环,理解为什么它确定性且易重复
- 说明 temperature 的数学性质:T→0 等价 greedy,T→∞ 等价均匀分布
- 实现 top-k 和 top-p filter,解释为什么 top-p 比 top-k 更灵活
- 实现 repetition penalty 的正负分支处理,理解为什么不能统一除以 penalty
- 追踪 KV cache 的 shape 变化,解释 $O(T^2) \to O(T)$ 的加速原理
- 说出 `generate` 中采样策略的执行顺序:temperature → rep penalty → top_k → top_p → multinomial
- 解释 minimind 为什么手写 `generate` 覆盖 HF 的 `GenerationMixin`

## 术语表

| 术语 | 英文 | 解释 |
|---|---|---|
| 自回归 | Autoregressive | 每步输出依赖之前所有输出;LLM 生成的核心特征 |
| 贪心解码 | Greedy Decoding | 每步选 argmax(logits);确定性,易重复 |
| 温度 | Temperature | logits 缩放因子 T;T 小→尖锐,T 大→平坦 |
| 核采样 | Top-p / Nucleus | 保留累积概率达 p 的最小 token 集合;动态截断 |
| Top-k | Top-k Sampling | 保留概率最高的固定 k 个 token |
| 重复惩罚 | Repetition Penalty | 降低已出现 token 的 logit;正数除以、负数乘以 penalty |
| KV 缓存 | KV Cache | 缓存历史 Key/Value 向量,避免重复计算 |
| 采样 | Sampling | 从概率分布中随机抽取;`torch.multinomial` |
| 流式输出 | Streamer | 逐 token 输出,而非等全部生成完 |
| 推理模式 | Inference Mode | `@torch.inference_mode()`;关闭梯度追踪,省内存 |

## 采样策略执行顺序

```
logits
  │
  ├─ ① / temperature          (第 267 行)
  │
  ├─ ② repetition penalty     (第 268-270 行)  仅 penalty≠1 时
  │
  ├─ ③ top_k filter           (第 271-272 行)  仅 top_k>0 时
  │
  ├─ ④ top_p filter           (第 273-277 行)  仅 top_p<1 时
  │
  └─ ⑤ multinomial / argmax   (第 278 行)      do_sample 决定
```

> 先缩放,再惩罚重复,再双重截断,最后采样。每一步都在缩小候选空间。

## KV Cache 复杂度对比

| 生成长度 | 朴素 O(T²) | KV cache O(T) | 加速比 |
|---|---|---|---|
| 50 | ~1,300 | ~53 | ~25× |
| 200 | ~20,000 | ~203 | ~100× |
| 1000 | ~500,000 | ~1,003 | ~500× |

> 这也是为什么 `use_cache=True` 是 minimind 的默认值 —— 关掉它生成速度慢一到两个数量级。

## 核心认知

> 生成是 LLM 的「出口」—— logits 是连续的概率空间,生成策略是这个空间到离散 token 序列的**采样映射**。理解 temperature / top-k / top-p / repetition penalty 的叠加效果,你就能精确控制模型的输出风格:从精确的事实回答(T=0.1)到创意写作(T=1.0, top_p=0.95)。而 KV cache 把 $O(T^2)$ 的朴素自回归降到 $O(T)$,是推理性能的命脉。
