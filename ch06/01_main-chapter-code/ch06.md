# 第 6 章导读:模型组装 —— 嵌入 → 堆叠 Block → lm_head → 绑定权重

> 这是 MiniMind 教程的第 6 章。完整的交互版见 [`ch06.ipynb`](./ch06.ipynb)。

## 章节摘要

前 3 章(第 3-5 章)我们逐个拆解了 minimind 的零件:Config 超参数、RMSNorm、RoPE、Attention、FeedForward、Block。本章是**总装车间** —— 把这些零件拼成一台完整的引擎。

本章对应 `model_minimind.py` 的 **196-253 行**:
- `MiniMindModel`(196-232):backbone —— embed_tokens + N 个 Block + final norm + RoPE buffer
- `MiniMindForCausalLM`(234-253):在 backbone 上加 lm_head + CE loss + 权重绑定

核心是**完整 forward pass 的 tensor shape 追踪** —— 用代码逐步打印每一步的形状变化。

## 学习目标

读完本章后,你应该能:

- 解释 `nn.Embedding` 如何把 token id 查表变成向量,以及为什么它是可学习的
- 说出 `MiniMindModel.forward` 中 `start_pos` 的计算逻辑和 RoPE 窗口切片原理
- 理解 `register_buffer(persistent=False)` 的含义和为什么 RoPE 表不存入 state_dict
- 解释**权重绑定(tied embeddings)**的机制:为什么 `embed_tokens.weight is lm_head.weight`
- 从 `input_ids` 到 `loss` 追踪完整 forward pass 中每一步的 tensor shape
- 解释 CE loss 的 shift-by-1 对齐和 `ignore_index=-100` 的作用
- 手动拆解 64M 模型的参数量,验证 `sum(p.numel() for p in model.parameters())`

## 术语表

| 术语 | 英文 | 解释 |
|---|---|---|
| 嵌入 | Embedding | 把离散的 token id 映射到连续高维向量空间;`nn.Embedding` 是查表操作 |
| 骨干网络 | Backbone | `MiniMindModel`:embed → N×Block → norm,负责编码 |
| 语言模型头 | lm_head | `nn.Linear(hidden_size, vocab_size)`,把 hidden_state 映射到 logits |
| 绑定权重 | Tied Embeddings | 输入 embedding 和输出 lm_head 共享同一套权重矩阵 |
| 缓冲区 | Buffer | `register_buffer` 注册的非学习张量,随模型迁移设备但不被 optimizer 更新 |
| 非持久化 | Non-persistent | `persistent=False` 的 buffer 不出现在 state_dict 中 |
| 起始位置 | start_pos | 从 KV cache 长度推算的位置偏移,用于切正确 RoPE 窗口 |
| 交叉熵损失 | Cross-Entropy Loss | 分类任务的标准损失函数;语言模型用它做 next-token 预测 |
| 忽略索引 | ignore_index | CE loss 中标记为该值的 label 不参与计算(默认 -100) |
| 辅助损失 | aux_loss | MoE 的负载均衡损失,确保 router 均匀分配 token 给各 expert |
| Logits | Logits | lm_head 输出,每个位置对词表所有 token 的未归一化分数 |
| 移位对齐 | Shift by 1 | `logits[:, :-1]` 对齐 `labels[:, 1:]`,实现 next-token 预测 |

## 核心认知

> 一个完整的 LLM forward pass 就是一条张量流水线:`(b, T)` → `(b, T, 768)` → `(b, T, 6400)` → scalar。每一步的 shape 变化都是可预测的、可追踪的。理解了这条流水线,你就理解了 Transformer 的骨架。
